មិនប៉ះពាល់ល្បឿន

Python មិនពិនិត្យ annotation នៅពេលដំណើរការទេ

Warning

Python មិនរារាំងទេ បើអ្នកបញ្ជូនប្រភេទខុស៖

>>> def double(n: int) -> int:
...     return n * 2
...
>>> double(5)
10
>>> double("ab")            # មិនមានកំហុសទេ!
'abab'

Type hint គឺជា ឯកសារដែលម៉ាស៊ីនអានបាន មិនមែនជាការត្រួតពិនិត្យ ពេលដំណើរការទេ។ ដើម្បីទទួលបានអត្ថប្រយោជន៍ អ្នកត្រូវដំណើរការ type checker (mypy, pyright) ជាផ្នែកនៃ CI របស់អ្នក។

វាក្យសម្ពន្ធមូលដ្ឋាន

# Parameter និងតម្លៃត្រឡប់
def greet(name: str, times: int = 1) -> str:
    return f"សួស្ដី {name}! " * times


# អថេរ
count: int = 0
names: list[str] = []
config: dict[str, int] = {"timeout": 30}

# ប្រកាសដោយមិនផ្ដល់តម្លៃ
total: float

# ថេរកម្រិត module
MAX_RETRIES: int = 3

>>> greet.__annotations__
{'name': <class 'str'>, 'times': <class 'int'>, 'return': <class 'str'>}
>>> count.__class__.__name__
'int'

def top_scores(scores: dict[str, int], n: int = 3) -> list[tuple[str, int]]:
    """ត្រឡប់ពិន្ទុខ្ពស់បំផុត n ។"""
    return sorted(scores.items(), key=lambda kv: kv[1], reverse=True)[:n]

>>> top_scores({"math": 87, "physics": 92, "chem": 78, "bio": 95}, 2)
[('bio', 95), ('physics', 92)]

None, NoReturn និង Never

-> None

អនុគមន៍ដែលមិនត្រឡប់អ្វីមានន័យ (ត្រឡប់ None)

-> NoReturn

អនុគមន៍ដែល មិនដែលត្រឡប់ ដោយធម្មតា — បញ្ចេញ exception ឬ sys.exit()

-> Never

ដូច NoReturn (3.11+) — ឈ្មោះច្បាស់ជាង។ NoReturn គឺជា alias

None ជាប្រភេទ

ប្រភេទនៃ object None ផ្ទាល់ (NoneType)

 
import sys
from typing import Never, NoReturn


def fail(message: str) -> Never:
    """មិនដែលត្រឡប់ទេ។"""
    raise SystemExit(message)


def quit_app(code: int = 0) -> NoReturn:
    sys.exit(code)


def log(message: str) -> None:
    print(message)

Note

Never មានប្រយោជន៍ពិសេសក្នុងការពិនិត្យ exhaustiveness។ សូមមើលផ្នែក TypeGuard និង TypeIs។

from collections.abc import Callable


def apply(func: Callable[[int, int], int], a: int, b: int) -> int:

result = apply(add, 3, 4)          # 7

from typing import NamedTuple, NotRequired, TypedDict
from dataclasses import dataclass


class UserDict(TypedDict):
    id: int
    name: str
    email: NotRequired[str]


class UserTuple(NamedTuple):
    id: int
    name: str
    email: str = ""


@dataclass
class UserClass:
    id: int
    name: str
    email: str = ""

>>> u1: UserDict = {"id": 1, "name": "សុខា"}
>>> u1["name"]
'សុខា'
>>> u2 = UserTuple(2, "ដារ៉ា")
>>> u2.name, u2[0]
('ដារ៉ា', 2)
>>> u3 = UserClass(3, "សុភា")
>>> u3
UserClass(id=3, name='សុភា', email='')

Note

TypedDict គ្រាន់តែជា dict ធម្មតានៅពេលដំណើរការ — Python មិន បង្កើតប្រភេទថ្មី ឬពិនិត្យ key ទេ។ វាមានប្រយោជន៍តែសម្រាប់ type checker។

NotRequired[...] (3.11+) បញ្ជាក់ថា key នេះអាចអវត្តមាន។ Required[...] បញ្ជាក់ផ្ទុយវិញ (មានប្រយោជន៍ក្នុង TypedDict ដែលមាន total=False)។

Protocol — Structural Typing

Added in version 3.8.

Protocol អនុញ្ញាតឱ្យអ្នកកំណត់ interface ដោយមិនចាំបាច់ inheritance៖

from typing import Protocol, runtime_checkable


@runtime_checkable
class Drawable(Protocol):
    """Object ណាក៏បានដែលមាន method draw()។"""

    def draw(self) -> str: ...


class Circle:                          # មិនបានប្រកាសថា implement ទេ
    def draw(self) -> str:
        return "○"


class Square:
    def draw(self) -> str:
        return "□"


def render(shapes: list[Drawable]) -> str:
    return " ".join(s.draw() for s in shapes)

>>> render([Circle(), Square()])
'○ □'
>>> isinstance(Circle(), Drawable)     # ត្រូវការ @runtime_checkable
True
>>> isinstance("not drawable", Drawable)
False

Note

នេះហៅថា structural typing ("static duck typing") — ប្រភេទត្រូវបាន កំណត់ដោយ រចនាសម្ព័ន្ធ ដែល object មាន មិនមែនដោយឈ្មោះ class ដែលវាប្រកាសទេ។ វាខុសពី abc.ABC ដែលតម្រូវឱ្យប្រកាស inheritance ដោយច្បាស់ (nominal typing)។

@runtime_checkable ធ្វើឱ្យ isinstance() ដំណើរការ ប៉ុន្តែវាពិនិត្យ តែ វត្តមាន method មិនមែន signature ទេ។

TypeVar និង Generic

TypeVar អនុញ្ញាតឱ្យអ្នកសរសេរកូដដែល រក្សាប្រភេទ តាមរយៈការហៅ៖

# ទម្រង់ចាស់
from typing import TypeVar, Generic

T = TypeVar("T")


def first_old(items: list[T]) -> T:
    return items[0]

# ទម្រង់ថ្មី (3.12+) — PEP 695
def first[T](items: list[T]) -> T:
    return items[0]


class Stack[T]:
    def __init__(self) -> None:
        self._items: list[T] = []

    def push(self, item: T) -> None:
        self._items.append(item)

    def pop(self) -> T:
        return self._items.pop()

>>> first([1, 2, 3])          # checker ដឹងថាត្រឡប់ int
1
>>> first(["a", "b"])         # checker ដឹងថាត្រឡប់ str
'a'

ប្រៀបធៀបជាមួយ ``Any``៖

from typing import Any


def first_any(items: list[Any]) -> Any:   # ❌ បាត់បង់ព័ត៌មានប្រភេទ
    return items[0]


def first_t[T](items: list[T]) -> T:      # ✅ រក្សាប្រភេទ
    return items[0]

Note

TypeVar អាចមាន constraint ឬ bound៖

from typing import TypeVar

# ត្រូវតែជាប្រភេទណាមួយក្នុងបញ្ជី
StrOrBytes = TypeVar("StrOrBytes", str, bytes)

# ត្រូវតែជា subclass នៃ bound
NumberT = TypeVar("NumberT", int, float)

PEP 695 ផ្ដល់វាក្យសម្ពន្ធខ្លីជាង៖ def f[T: (str, bytes)](...) និង def g[T: int](...)។

Added in version 3.13: TypeVar អាចមាន តម្លៃលំនាំដើម (PEP 696)៖ T = TypeVar("T", default=int)។

ParamSpec — រក្សា Signature

Added in version 3.10.

ParamSpec អនុញ្ញាតឱ្យ decorator រក្សា signature ពេញលេញនៃអនុគមន៍ ដែលវា decorate៖

from collections.abc import Callable
from typing import ParamSpec
import functools

P = ParamSpec("P")
R = TypeVar("R")


def logged(func: Callable[P, R]) -> Callable[P, R]:
    """រក្សាទាំង parameter និងតម្លៃត្រឡប់។"""

    @functools.wraps(func)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        print(f"ហៅ {func.__name__}")
        return func(*args, **kwargs)

    return wrapper


@logged
def divide(a: int, b: int) -> float:
    return a / b

>>> import inspect
>>> inspect.signature(divide)
<Signature (a: int, b: int) -> float>
>>> divide(10, 4)
ហៅ divide
2.5

Note

បើគ្មាន ParamSpec អ្នកត្រូវប្រើ Callable[..., R] ដែលបាត់បង់ ព័ត៌មាន parameter។ P.args និង P.kwargs តំណាងឱ្យ positional និង keyword argument រៀងៗខ្លួន។

typing.Concatenate[X, P] អនុញ្ញាតឱ្យ decorator បន្ថែម ឬដក parameter មួយ។

Self និង ClassVar

from typing import ClassVar, Self


class Builder:
    version: ClassVar[str] = "1.0"      # របស់ class មិនមែន instance

    def __init__(self) -> None:
        self.parts: list[str] = []

    def add(self, part: str) -> Self:   # ត្រឡប់ instance នៃ class បច្ចុប្បន្ន
        self.parts.append(part)
        return self


class SubBuilder(Builder):
    pass

>>> b = Builder().add("a").add("b")     # chaining
>>> b.parts
['a', 'b']
>>> s = SubBuilder().add("x")
>>> type(s).__name__                    # ✅ SubBuilder មិនមែន Builder
'SubBuilder'

Note

Self (3.11+) មានប្រយោជន៍សម្រាប់ method ដែលត្រឡប់ instance ខ្លួនឯង (fluent interface)។ បើអ្នកសរសេរ -> "Builder" នោះ SubBuilder().add() នឹងត្រូវបាន checker យល់ថាត្រឡប់ Builder។

ClassVar ប្រាប់ type checker ថា attribute នេះជារបស់ class មិនមែន instance។ @dataclass ក៏មិនចាត់ទុក ClassVar ជា field ដែរ។

TypeGuard និង TypeIs

Type narrowing — ប្រាប់ type checker ថាប្រភេទត្រូវបានកំណត់ច្បាស់ ក្នុង scope មួយ៖

from typing import TypeGuard, TypeIs, assert_never


def is_str_list_old(val: list[object]) -> TypeGuard[list[str]]:
    return all(isinstance(x, str) for x in val)


def is_str_list(val: list[object]) -> TypeIs[list[str]]:
    return all(isinstance(x, str) for x in val)

ភាពខុសគ្នា

TypeGuard[X] (3.10+)

បើ True → ប្រភេទគឺ X។ បើ False → ប្រភេទដើម មិនផ្លាស់ប្ដូរ

TypeIs[X] (3.13+)

បើ True → X។ បើ False → ប្រភេទដើម ត្រូវបានធ្វើឱ្យតូច ដោយដក X ចេញ។ ដូច isinstance() ពិតប្រាកដ

Tip

ប្រើ TypeIs សម្រាប់កូដថ្មី — វាមានឥរិយាបថស្របនឹងអ្វីដែល អ្នកសរសេរកូដរំពឹង។ TypeGuard នៅតែមានប្រយោជន៍ពេលអ្នកចង់ បំលែងប្រភេទទាំងស្រុង (ឧ. ពី JSON dict ទៅ dataclass)។

Exhaustiveness check ជាមួយ assert_never៖

from typing import Literal, assert_never


def describe(value: Literal["a", "b"]) -> str:
    if value == "a":
        return "អក្សរ a"
    elif value == "b":
        return "អក្សរ b"
    else:
        # បើមានតម្លៃថ្មីត្រូវបានបន្ថែមទៅ Literal ខាងលើ
        # type checker នឹងបញ្ចេញកំហុសនៅទីនេះ
        assert_never(value)

@override

Added in version 3.12.

from typing import override


class Base:
    def process(self) -> None:
        ...


class Child(Base):
    @override                        # បញ្ជាក់ថា override method របស់ class មេ
    def process(self) -> None:
        ...

បើ Base.process ត្រូវបានប្ដូរឈ្មោះ ឬលុប type checker នឹងបញ្ចេញ កំហុសលើ Child.process។ នេះការពារកំហុសនៅពេល refactor។

PEP 649 — Annotation ដំណើរការយឺត

Changed in version 3.14: Annotation ត្រូវបានវាយតម្លៃ យឺត (lazily)។ __annotations__ ត្រូវបានគណនានៅពេលអ្នកចូលដំណើរការវា មិនមែននៅពេលកំណត់អនុគមន៍ទេ។

អត្ថប្រយោជន៍៖

  • អ្នកអាចយោងទៅ class ដែល មិនទាន់បានកំណត់ ដោយមិនចាំបាច់ខ្សែអក្សរ៖

    class Node:
    def child(self) -> Node:      # ✅ ដំណើរការ — មិនចាំបាច់ "Node"
        ...

  • ការនាំចូល module លឿនជាង ព្រោះ annotation មិនត្រូវបានវាយតម្លៃ។

Note

from __future__ import annotations (PEP 563) ធ្វើឱ្យ annotation ទាំងអស់ក្លាយជា ខ្សែអក្សរ។ វានៅតែដំណើរការ ប៉ុន្តែ PEP 649 ជាដំណោះស្រាយផ្លូវការចាប់ពី 3.14។ សម្រាប់កូដថ្មី អ្នកមិនចាំបាច់ from __future__ import annotations ទៀតទេ។

បើអ្នកប្រើ typing.get_type_hints() លើកូដដែលមាន from __future__ import annotations អ្នកត្រូវធានាថាឈ្មោះទាំងអស់ អាចដោះស្រាយបានក្នុង scope របស់ module។

ការអនុវត្តល្អបំផុត

  1. ចាប់ផ្ដើមត្រង់ព្រំដែន — annotate អនុគមន៍សាធារណៈ API boundary និងទិន្នន័យដែលមកពីខាងក្រៅជាមុន។ កូដផ្ទៃក្នុងអាចបន្ថែមបន្តិចម្ដងៗ។

  2. Gradual typing — អ្នកមិនចាំបាច់ annotate គ្រប់យ៉ាងទេ។ Python អនុញ្ញាតឱ្យលាយឡំកូដដែលមាន និងគ្មាន annotation។

  3. កុំប្រើ ``Any`` ដើម្បីបំបាត់កំហុស — វាបិទការត្រួតពិនិត្យទាំងស្រុង។ បើចាំបាច់ ប្រើ object វិញ ដែលនៅតែតម្រូវឱ្យពិនិត្យប្រភេទមុនប្រើ។

  4. ប្រើប្រភេទ built-in generic (list[int] មិនមែន List[int])។

  5. ប្រើ ``X | None`` ជាជាង Optional[X] ក្នុងកូដថ្មី។

  6. ប្រើ PEP 695 syntax (def f[T](...), type X = ...) សម្រាប់ គម្រោងដែលតម្រូវ Python 3.12+។

  7. ដំណើរការ type checker ក្នុង CI — annotation ដែលមិនត្រូវបាន ពិនិត្យគឺគ្រាន់តែជាអត្ថាធិប្បាយដែលអាចខុសបាន។

  8. កុំពឹងផ្អែកលើ annotation សម្រាប់ validation — សម្រាប់ទិន្នន័យ ពីអ្នកប្រើ ប្រើបណ្ណាល័យដូចជា pydantic ឬការពិនិត្យដោយផ្ទាល់។

  9. Annotate ``self`` និង ``cls`` មិនចាំបាច់ — type checker ដឹងរួចហើយ។

  10. ប្រើ ``from __future__ import annotations`` តែនៅពេលអ្នកត្រូវការ គាំទ្រ Python < 3.10 ហើយចង់បានវាក្យសម្ពន្ធ X | Y។
