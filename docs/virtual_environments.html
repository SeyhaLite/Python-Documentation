Virtual Environments និង Packages

ហេតុអ្វីត្រូវការ Virtual Environment?

កម្មវិធី Python ជាច្រើនប្រើ package ដែលមិនមែនជាផ្នែកនៃបណ្ណាល័យស្តង់ដារ។ ជួនកាលកម្មវិធីពីរត្រូវការ កំណែខុសគ្នា នៃបណ្ណាល័យដូចគ្នា៖

កម្មវិធី A  →  ត្រូវការ requests 2.28
កម្មវិធី B  →  ត្រូវការ requests 2.32

បើអ្នកដំឡើងទាំងពីរក្នុង Python តែមួយ វានឹង ប៉ះទង្គិចគ្នា។

Virtual environment គឺជាថតដាច់ដោយឡែកមួយដែលមានការដំឡើង Python ផ្ទាល់ខ្លួន និង package ផ្ទាល់ខ្លួន។ កម្មវិធីនីមួយៗអាចមាន environment របស់វា ដោយមិនរំខានគ្នា។

អត្ថប្រយោជន៍

អត្ថប្រយោជន៍

ការពន្យល់

ដាច់ស្រឡះ

គម្រោងនីមួយៗមាន dependency ផ្ទាល់ខ្លួន មិនប៉ះទង្គិចគ្នា

ស្អាត

មិនបំពុល Python របស់ប្រព័ន្ធ

អាចធ្វើម្ដងទៀតបាន

requirements.txt ឬ pyproject.toml អនុញ្ញាតឱ្យអ្នកផ្សេងដំឡើងដូចគ្នា

មិនត្រូវការសិទ្ធិ admin

មិនចាំបាច់ sudo ដើម្បីដំឡើង package

ការបង្កើត Virtual Environment

$ cd my-project
$ python3 -m venv .venv

  • -m venv ដំណើរការម៉ូឌុល venv ជា script។

  • .venv គឺជាឈ្មោះថត។ អនុសញ្ញាទូទៅគឺ .venv ឬ venv។

Important

ប្រើ interpreter ជាក់លាក់ បើអ្នកចង់បានកំណែជាក់លាក់៖

$ python3.15 -m venv .venv     # environment សម្រាប់ Python 3.15
$ py -3.13 -m venv .venv       # Windows — ជ្រើសរើសកំណែ

venv ដំឡើងកំណែ Python ដែល បានដំណើរការពាក្យបញ្ជា នោះ។

ការធ្វើឱ្យសកម្ម (Activate)

ប្រព័ន្ធ / Shell

ពាក្យបញ្ជា

Linux / macOS (bash, zsh)

source .venv/bin/activate

Linux / macOS (fish)

source .venv/bin/activate.fish

Linux / macOS (csh/tcsh)

source .venv/bin/activate.csh

Windows (Command Prompt)

.venv\\Scripts\\activate.bat

Windows (PowerShell)

.venv\\Scripts\\Activate.ps1

 
$ source .venv/bin/activate
(.venv) $ python --version
Python 3.15.0
(.venv) $ which python
/home/user/my-project/.venv/bin/python

សញ្ញា (.venv) នៅមុខ prompt បញ្ជាក់ថា environment កំពុងសកម្ម។

បិទ (deactivate)៖

(.venv) $ deactivate
$

Note

អ្នក មិនចាំបាច់ activate ទេ — អ្នកអាចហៅ interpreter ដោយផ្ទាល់៖

$ .venv/bin/python app.py
$ .venv/bin/pip install requests

នេះមានប្រយោជន៍ក្នុង script ឬ CI ដែលការ activate មិនងាយស្រួល។

រចនាសម្ព័ន្ធនៃ Virtual Environment

.venv/
├── bin/                    (Windows: Scripts\)
│   ├── python  →  python3.15
│   ├── pip
│   └── activate
├── include/
├── lib/
│   └── python3.15/
│       └── site-packages/  ← package របស់អ្នកនៅទីនេះ
└── pyvenv.cfg              ← កំណត់រចនាសម្ព័ន្ធ

Important

ដាក់ ``.venv/`` ក្នុង ``.gitignore``។ កុំ commit environment ទេ — វាធំ អាស្រ័យលើប្រព័ន្ធ និងអាចបង្កើតឡើងវិញបានពី requirements.txt។

# .gitignore
.venv/
venv/
__pycache__/
*.py[cod]

pip — ការគ្រប់គ្រង Package

pip គឺជាឧបករណ៍ដំឡើង package ស្តង់ដារ ដែលមកជាមួយ Python។

ពាក្យបញ្ជា

ការប្រើប្រាស់

pip install requests

ដំឡើងកំណែចុងក្រោយ

pip install "requests==2.32.3"

ដំឡើងកំណែជាក់លាក់

pip install "requests>=2.31,<3"

ដំឡើងក្នុងជួរកំណែ

pip install -U requests

ធ្វើបច្ចុប្បន្នភាព

pip uninstall requests

ដកចេញ

pip list

រាយ package ទាំងអស់ដែលបានដំឡើង

pip list --outdated

រាយ package ដែលមានកំណែថ្មីជាង

pip show requests

ព័ត៌មានលម្អិតអំពី package មួយ

pip freeze

បញ្ចេញជាទម្រង់ name==version

pip install -r requirements.txt

ដំឡើងពីឯកសារ

pip check

ពិនិត្យ dependency ដែលបែកបាក់

pip download pkg -d ./wheels

ទាញយកដោយមិនដំឡើង

 
(.venv) $ pip install requests

Note

pip ដំឡើង dependency ដោយស្វ័យប្រវត្តិ។ ក្នុងឧទាហរណ៍ខាងលើ requests ទាញយក charset-normalizer, idna, certifi និង urllib3 ផងដែរ។

requirements.txt

វិធីសាមញ្ញបំផុតដើម្បីកត់ត្រា dependency៖

PEP 668 — externally-managed-environment

Added in version 3.11.

Distribution Linux ជាច្រើន (Debian 12+, Ubuntu 23.04+, Fedora 38+) បាន សម្គាល់ Python របស់ប្រព័ន្ធថា គ្រប់គ្រងដោយខាងក្រៅ។ នេះមានន័យថា pip install ទៅប្រព័ន្ធនឹងបរាជ័យ៖

error: externally-managed-environment
× This environment is externally managed
╰─> To install Python packages system-wide, try apt install python3-xyz...

នេះគឺជាការការពារ មិនមែនជាកំហុសទេ។ ឧបករណ៍ប្រព័ន្ធជាច្រើនពឹងផ្អែក លើ Python របស់ប្រព័ន្ធ ហើយ pip អាចបំបែកវា។

ដំណោះស្រាយត្រឹមត្រូវ៖

# ១. Virtual environment (ណែនាំសម្រាប់គម្រោង)
$ python3 -m venv .venv && source .venv/bin/activate
$ pip install requests

# ២. pipx (ណែនាំសម្រាប់ឧបករណ៍ CLI)
$ pipx install black

# ៣. apt (សម្រាប់ package ប្រព័ន្ធ)
$ sudo apt install python3-requests

Warning

uv

ឧបករណ៍គ្រប់គ្រងគម្រោង និង package សរសេរជា Rust។ លឿនជាង pip ច្រើនដង អាចជំនួស venv, pip, pip-tools, pyenv។ uv venv, uv pip install, uv run

pipx

ដំឡើងឧបករណ៍ CLI ក្នុង environment ដាច់ដោយឡែក។ pipx install black

poetry

គ្រប់គ្រង dependency + build + publish។ ប្រើ pyproject.toml និង lock file

pdm

ដូច poetry ប៉ុន្តែអនុវត្តតាម PEP 582

pip-tools

pip-compile បង្កើត requirements.txt ដែលបានខ្ទាស់ពី .in file

conda / mamba

សម្រាប់វិទ្យាសាស្ត្រទិន្នន័យ — គ្រប់គ្រងទាំង package មិនមែន Python

pyenv

គ្រប់គ្រង កំណែ Python ច្រើន (មិនមែន package)

Tip

សម្រាប់អ្នកចាប់ផ្ដើម venv + pip គឺគ្រប់គ្រាន់។ នៅពេលគម្រោងធំឡើង សូមពិចារណា uv (លឿន និងសាមញ្ញ) ឬ poetry (lock file និង dependency resolution ខ្លាំង)។

uv អាចបង្កើត environment និងដំឡើង package ក្នុងពាក្យបញ្ជាតែមួយ៖

$ uv venv                     # បង្កើត .venv
$ uv pip install requests     # ដំឡើង
$ uv run app.py               # ដំណើរការក្នុង environment

ការអនុវត្តល្អបំផុត

  1. បង្កើត virtual environment សម្រាប់គម្រោងនីមួយៗ — គ្មានករណីលើកលែង។

  2. ដាក់ ``.venv/`` ក្នុង ``.gitignore`` — commit តែ requirements.txt ឬ pyproject.toml។

  3. ខ្ទាស់កំណែ សម្រាប់ deployment (==) ប្រើជួរ (>=, ~=) សម្រាប់ library។

  4. កុំប្រើ ``sudo pip`` ឬ --break-system-packages។

  5. ដំណើរការ ``pip check`` ក្នុង CI ដើម្បីរក dependency បែកបាក់។

  6. ប្រើ lock file (uv.lock, poetry.lock, requirements.txt ដែលបាន compile) ដើម្បីធានាការដំឡើងដូចគ្នាគ្រប់ទីកន្លែង។

  7. ញែក dev dependency ពី runtime dependency ([project.optional-dependencies] dev = [...])។

  8. ដំឡើងឡើងវិញពីសូន្យ ជាការសាកល្បង — បើ pip install -r មិនដំណើរការលើ machine ស្អាត នោះគម្រោងរបស់អ្នកមិនអាចធ្វើម្ដងទៀតបានទេ។

  9. ធ្វើបច្ចុប្បន្នភាពជាទៀងទាត់ — pip list --outdated។
